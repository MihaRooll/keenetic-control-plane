# Ужать контекст (compact-context)

## Цель

Сжать историю текущего чата в **плотный continuation packet**, чтобы можно было продолжить работу с меньшим контекстом (часто — в новом чате). Skill **не очищает** окно Cursor сам; результат — текст, который пользователь копирует дальше.

## Шаги

1. Прочитай только то, что уже есть в этом чате + при необходимости актуальный `docs/STATUS.yaml` / `next_task` (не раздувай ответ чтением всего репо).
2. Выдай **один** markdown-блок ниже. Без преамбулы, без «как пользоваться», без повторов.
3. Лимит: **~40–80 строк** / ориентир **≤1200 слов**. Режь болтовню; оставляй факты, пути, команды, блокеры.
4. **Секреты запрещены:** пароли, ключи, tokens, raw sessions, startup-config, credentials — никогда не копируй; пиши `credential_ref` / «в vault».
5. В конце одной строкой: что делать дальше — `Новый чат → вставь этот блок` или `Продолжай здесь с этим handoff`.

## Формат ответа (строго)

```markdown
# Context compact — YYYY-MM-DD

## Goal
[1–2 предложения: чего добиваемся]

## Done
- [факт / путь / команда с exit 0]
- …

## In progress
- [что не закончено]

## Decisions (keep)
- [решения, которые нельзя потерять]

## Blockers / Human gates
- [или «нет»]

## Key paths
- `path/to/file` — зачем
- …

## Next 1–3 steps
1. …
2. …
3. …

## Verify
```text
[команды проверки, если были / нужны]
```

## Do not claim
- [что ещё нельзя утверждать]
```

## Правила качества

- Пиши по-русски; пути/команды/SSOT-идентификаторы — as is.
- Не выдумывай статус роутера, Gate A, `next_task` — только из чата или `STATUS.yaml`.
- Если чат почти пустой — скажи коротко и спроси цель, не заполняй шаблон выдумкой.
- Не коммить и не править файлы, пока пользователь явно не попросил сохранить handoff на диск.
